# SLAI Pet 交互与共生体验补充说明

状态：方案补充；第 3.1 节的事件协议与降级演出已进入当前未提交工作树
日期：2026-08-22
适用阶段：`0.1.x` 加固至 `0.6.0` 共生体验建设

当前实现边界：`pet_state_changed`、`pet_reaction` 和确定性 `ReactionPlan` v1 已实现，
页面已有状态更新、头顶气泡、小鱼粒子和 Live2D 画布高亮。`mao_pro` 原生吃东西动作、
专用音效以及真实 LLM/MCP 全链路验收仍属于后续工作。

## 1. 目的与当前缺口

这份说明补充 SLAI Pet 在互动反馈、生活节奏、主动沟通、界面表现、视觉美化、
宠物世界、记忆和性格方面的产品与技术方向。它描述“下一步应怎样设计”，不代表这些
能力已经完成。

当前代码已经具备真实宠物状态、喂食领域服务、SQLite 持久化、HTTP 状态卡、MCP
工具、Live2D 表情和 TTS，但体验仍有以下断层：

- 喂食可以改变数据库状态，却没有统一的“状态变化 → 动作 → 气泡 → 音效 → 页面”
  反应编排；自然语言喂食也缺少端到端验收。
- 页面主要通过 HTTP 加载和 60 秒轮询状态，尚无正式的 `pet_state_changed` 事件。
- 宠物没有可持久化的日程、行为状态机、世界时间线和主动沟通策略。
- 聊天气泡、长期记忆侧栏、场景变化和摄像头边缘美化尚未形成统一体验。
- 当前只有小太阳“小光”一套正式人格；基础成长字段存在，但世界、长期记忆和完整
  PersonaPack 尚未实现。

## 2. 总体设计原则

所有入口应共用同一条可审计链路：

```text
用户对话 / UI 操作 / 定时器 / 授权感知
                  ↓
            结构化领域事件
                  ↓
      状态、世界、记忆与主动策略
                  ↓
             ReactionPlan
                  ↓
Live2D 动作 + 气泡 + TTS + 音效 + 背景 + 状态卡
```

核心原则：数据库和领域事件决定“发生了什么”，人格决定“怎样表达”，前端只负责
“怎样演出”。LLM 可以生成自然语言，但不能凭文字假装喂食、生活事件或记忆已经发生。

## 3. 六项体验补充

### 3.1 喂小鱼干后立即产生可见反应

增加统一的 `ReactionPlan`（反应计划）和前端反应编排器。无论喂食来自聊天中的
`feed_pet` 工具调用，还是状态卡按钮，都由同一个 `PetStateService` 完成业务操作，并在
事务成功后发布两个结构化事件：

- `pet_state_changed`：携带 schema 版本、事件 ID、状态快照和字段差量。
- `pet_reaction`：携带动作、表情、气泡、音效、粒子效果和建议持续时间。

一次喂食的建议演出顺序：

1. 状态卡立即显示“正在吃”，按钮进入短暂冷却。
2. Live2D 播放吃东西动作；模型没有专用动作时，降级为开心表情、轻微弹跳和小鱼干粒子。
3. 人物头顶出现短气泡，例如“好香！谢谢你呀！”；同时播放咀嚼音效或轻提示音。
4. 饥饿、心情、亲密度等状态条平滑过渡到新值。
5. TTS 播放基于真实工具结果生成的回复，结束后恢复当前行为。

前端应按 `event_id` 去重，并向反应编排器提供优先级：用户即时互动高于普通待机行为，
但低于安全或错误提示。必须添加“自然语言喂食 → MCP → SQLite → WebSocket → UI/动作/
气泡/TTS”的可重复端到端验收。

### 3.2 为人物建立生活、节奏、行为和场景变化

引入三个受控模块：

- `WorldClock`：维护本地时间、日期、天气/节日等可选上下文，不自行伪造外部事实。
- `RoutineScheduler`：根据 PersonaPack 和用户设置生成可解释的日程槽，如起床、学习、
  玩耍、散步、写日记和睡觉。
- `BehaviorPlanner`：在用户互动、身体状态、日程和待机行为之间选择当前行为。

行为优先级建议为：用户即时操作 > 健康/状态告警 > 已到期日程 > 普通待机。每次切换写入
`WorldEvent`，包含起因、开始时间、预期结束时间和可用互动，重启后可以恢复，而不是只靠
前端计时器。

背景由世界状态映射到场景，例如早晨卧室、白天宠物学院、傍晚职业小镇、夜晚宠物家园；
切换采用渐变，并保留低性能模式。场景中的热点可以触发结构化互动，例如点击书桌后询问
“要一起学习还是休息”。

定时产出应是受控任务，而不是无限后台生成：

- 每日：一句日记或今日心情卡。
- 每周：一封信、一个小故事片段或一张纪念卡。
- 特殊事件：纪念日回顾、成长升级记录。

产出任务必须支持开关、安静时段、频率上限、失败重试、`request_id` 幂等和作品索引；
离线期间只补算重要事件摘要，不密集补播所有动画和消息。

### 3.3 让人物在合适时机主动沟通

增加 `ProactivePolicy`，由结构化触发器决定是否主动发起沟通，而不是让 LLM 自由轮询。
触发器可以包括日程完成、状态需要关心、新作品完成、纪念日、用户主动设置的提醒，以及
长时间无互动后的轻问候。

主动沟通必须满足：

- 用户明确开启；可分别控制气泡、语音和系统通知。
- 支持安静时段、每日上限、同类消息冷却和“一键今天别提醒”。
- 用户正在输入、通话、全屏或最近拒绝互动时不打断；无法确定时只显示静默气泡。
- 摄像头默认不作为主动打扰依据；若未来使用感知事件，必须单独授权并采用不确定措辞。
- 每条主动消息记录触发原因，用户可以查看“为什么现在找我”。

在线页面通过 `proactive_message` WebSocket 事件接收消息；页面不在线时仅在用户授权后使用
桌面通知。用户点击消息后进入普通对话，避免建立第二套聊天系统。

### 3.4 头顶气泡与侧边记忆查看

新增锚定 Live2D 模型的头顶气泡层。气泡位置根据模型可见区域和缩放动态计算，靠近窗口
边缘时自动翻转或收缩；短回复显示 3–8 秒，长回复允许展开，并兼顾字幕、键盘操作和
屏幕阅读器。内部 `[joy]` 等控制标签不得出现在气泡中。

侧边栏建议分成两个标签：

- “最近对话”：原始聊天历史，可按日期查看。
- “共同记忆”：经过确认或规则提取的 `MemoryRecord`，显示摘要、来源时间、置信度、
  隐私级别和被召回原因。

用户应能固定、编辑、更正、遗忘和导出自己的记忆。删除记忆时同时删除对应索引；宠物
不得把模型推断当作用户事实保存。

### 3.5 美化摄像头边缘并强化隐私提示

将摄像头预览改成可拖动的圆角画中画：使用圆角裁剪、轻阴影和可选的渐隐遮罩弱化硬边；
小尺寸时保持清晰边框，避免与背景混在一起。提供 16:9、圆形和隐藏预览三种显示模式，
并在移动、缩放和窄屏下保持不遮挡人物气泡与状态卡。

美化不能削弱隐私状态：摄像头启用时必须持续显示明显指示灯和“正在提供画面”提示，
关闭入口始终可见。原始帧只用于获授权的当前轮次，不进入项目记忆、日志或作品目录。

### 3.6 用世界、记忆和性格共同加持宠物

三者应分工明确：

| 模块 | 负责内容 | 不应负责 |
| --- | --- | --- |
| 宠物世界 | 时间、地点、日程、事件、场景和可互动对象 | 替代宠物真实状态或编造外部事实 |
| 宠物记忆 | 用户确认事实、共同经历、作品和召回证据 | 保存摄像头原始帧或无来源的人格推断 |
| 宠物性格 | 表达方式、偏好、行为权重、音色、形象和动作风格 | 绕过业务规则直接改数据库 |

PersonaPack 应原子绑定 System Prompt、音色、Live2D 模型、口头禅、动作映射、日程偏好、
主动沟通风格和记忆提取偏好。世界事件为人格提供“现在发生了什么”，记忆提供“我们曾经
经历什么”，人格据此决定“怎样理解和表达”，最终仍通过安全领域工具执行动作。

建议建立统一时间线，将 `PetEvent`、`WorldEvent`、`MemoryRecord` 和
`GeneratedArtifact` 用来源事件关联起来。这样一次共同学习可以同时改变成长值、成为世界
经历、形成可解释记忆，并在未来生成周记，而不需要四套互不一致的数据。

## 4. 推荐实施顺序

1. **即时互动闭环**：冻结 `PetState`、`pet_state_changed` 和 `pet_reaction` v1；先完成
   喂食演出与端到端验收。
2. **气泡与布局**：实现头顶气泡、摄像头圆角画中画和侧栏骨架，解决界面层冲突。
3. **生活纵向切片**：只实现一天内“休息 → 学习 → 玩耍”的最小日程、三种背景和离线恢复。
4. **主动沟通**：加入开关、安静时段、冷却、每日上限和可解释触发原因。
5. **长期记忆与作品**：冻结公共对象后，先做一类可编辑记忆和一种定时产出，再逐步扩展。
6. **完整 PersonaPack**：验证小太阳全链路后，再进行四人格原子切换。

不建议同时开发所有世界、记忆、作品和主动感知能力；每一步都应形成可观察、可关闭、
可测试的纵向闭环。

## 5. 最小验收标准

- 对话和按钮喂食都只改变一次真实状态，并在 1 秒内开始可见反馈。
- 动作不可用时有确定的降级效果，不出现“数据库已更新但人物毫无反应”。
- 宠物重启后能恢复当前状态、最近世界事件和未完成的受控任务。
- 主动消息遵守授权、安静时段、冷却和每日上限，并能解释触发原因。
- 气泡、状态卡、摄像头和记忆侧栏在常用窗口尺寸下不互相遮挡。
- 记忆可追溯、可更正、可删除；摄像头原始帧和凭据不进入记忆或日志。
- 人格切换同时影响文字、声音、形象、动作和行为偏好，不只替换提示词。

## 6. 需要产品负责人确认的选择

- 主动沟通默认关闭还是首次引导后开启，以及每日频率和默认安静时段。
- 第一批生活场景和背景资源范围，以及是否允许使用联网天气作为世界上下文。
- 第一种定时产出选择日记、信件还是纪念卡，以及是否允许自动保存本地文件。
- 共同记忆的默认保留周期、敏感内容分类和用户删除/导出方式。
- 现有 `mao_pro` 可用动作是否足够，还是需要新增 Live2D 动画与美术资源。
