# 关键决策记录

不要静默改写历史原因。

## D-001：以 Open-LLM-VTuber 1.2.1 为工程底座

- 日期：2026-08-21
- 状态：接受
- 决策：复用 FastAPI、WebSocket、ASR、TTS、Live2D、角色配置、历史和 MCP 框架。
- 原因：能最快建立可演示纵向闭环，同时把创新集中在宠物领域、记忆和共生世界。
- 影响：必须与上游代码边界保持清晰，并在计划窗口同步上游。

## D-002：使用单仓库并纳管前端普通目录

- 日期：2026-08-21
- 状态：接受
- 决策：将前端构建产物直接放入团队仓库，不依赖缺失或无权限的前端子模块。
- 原因：保证从空目录克隆后具备完整可运行界面。
- 影响：同步上游前端需要人工记录来源并跑回归。

## D-003：当前 LLM 使用 StepFun 视觉模型

- 日期：2026-08-21
- 状态：接受
- 决策：通过 OpenAI 兼容适配器调用 `step-1o-turbo-vision`，支持文本和图片。
- 原因：满足宠物同时结合语音转写与摄像头画面进行回应的需求。
- 影响：视觉轮次延迟和费用高于纯文本；配置必须支持视觉能力开关和错误降级。

## D-004：宠物状态由 SQLite 和领域服务负责

- 日期：2026-08-21
- 状态：接受
- 决策：`PetStateService` 是业务规则入口，`PetStateRepository` 保存 `data/pet.db`；模型只能通过安全工具读取/改变状态。
- 原因：避免前端或 LLM 口述成为虚假状态，支持幂等、审计事件和离线时间变化。
- 影响：后续状态动作必须进入领域服务，并通过迁移维护数据库 schema。

## D-005：人格由 Persona System Prompt 驱动

- 日期：2026-08-21
- 状态：接受
- 决策：人格绑定 Prompt、音色、形象、口头禅和动作；当前正式人格为小太阳“小光”。
- 原因：保证文字、声音和视觉表达一致，并让真实状态/安全规则拥有系统级约束。
- 影响：未来四人格切换必须作为原子配置切换，不能只替换提示词。

## D-006：表情标签是控制协议，不是可见文本

- 日期：2026-08-22
- 状态：接受
- 决策：`[joy]`、`[neutral]` 等标签继续触发 Live2D，但在气泡、字幕、历史展示和 TTS 中隐藏。
- 原因：用户不应看到或听到内部动作标记。
- 影响：新增表情必须同时更新模型映射、Prompt 和回归测试。
- 证据：提交 `b5b6a0d`。

## D-007：合并过短句子以平滑 TTS

- 日期：2026-08-22
- 状态：接受
- 决策：相邻语音文本累计达到约 12 个有效字符再生成一个音频单元；长句保持流式输出。
- 原因：Edge TTS 每个 SentenceOutput 生成独立文件，短片段过多会造成播放间隙和文字跳动。
- 影响：极短首句可能等待下一个句子，但总体播放更连续；表情动作列表会合并保留。
- 证据：提交 `9ae4276`。

## D-008：项目上下文以版本化 memory 目录维护

- 状态：接受
- 决策：使用根级 `AGENTS.md` 自动入口和 `memory/` 结构化文件维护项目上下文。
