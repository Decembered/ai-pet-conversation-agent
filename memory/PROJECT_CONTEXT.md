# 项目上下文

## 一句话定位

SLAI Pet 是一个运行在用户电脑中的情感化桌面宠物 Agent：它能够听见用户、看到
经用户授权提供的画面、保持真实状态、形成成长和共同回忆，并通过人格、音色、形象、
口头禅和 Live2D 动作一致地表达自己。

## 产品区别

项目目标不是给普通聊天机器人套一个 Live2D 形象，而是构建“共生世界”：

- 宠物状态由后端持久化数据决定，不依赖用户手动点击才能存在。
- Agent 能主动查询和调用安全业务工具，不能用文字假装状态已经变化。
- 人格是 System Prompt 与 PersonaPack，而不是临时用户提示词。
- 成长、关系、记忆、离线事件和生成作品应进入统一事件/记忆模型。
- 摄像头感知必须有授权、冷却、低风险措辞和隐私边界。

## 需求来源与优先级

需求冲突时采用以下顺序：

1. 项目负责人当前明确提出的需求。
2. 冻结后的统一需求与架构决策。
3. `prompt_excel.md` 中的功能预期和责任边界。
4. 课题评分与交付要求。
5. 初始需求文档。
6. Open-LLM-VTuber 上游能力。
7. 基础课程/PDF 架构参考。

## 版本目标

- `0.1.x`：小太阳人格、稳定 LLM、状态查询/喂食、持久化、UI、动作和 TTS 的纵向闭环。
- `0.2.0`：四人格的 Prompt、音色、形象、口头禅和动作原子切换。
- `0.3.0`：长期记忆、世界时间线和跨会话恢复。
- `0.4.0`：成长、绘画、写信、作品索引和预览。
- `0.5.0`：摄像头事件、主动调度、冷却和隐私控制。
- `0.6.0`：共同记忆馆、未完故事、回忆实体化等创新体验。
- `0.9.0`：发布候选；`1.0.0`：完整交付。

## 当前阶段边界

当前仍处于 `0.1.x` 纵向闭环加固阶段。新增大型能力前，优先确保：

- 对话触发 `get_pet_state` / `feed_pet` 的真实端到端验收稳定。
- 状态、前端、动作、字幕和语音结果一致。
- 配置无密钥、测试可重复、仓库可推送并可从空目录启动。

## 安全和隐私底线

- 不提交或输出 API Key、访问令牌和本地用户配置。
- 不保存摄像头原始帧作为项目记忆。
- 单帧表情只能使用“看起来”“好像”等不确定描述。
- 第一版不声称完成未经用户注册和确认的人脸身份识别。
- 工具调用必须经过业务服务和参数校验，不能让模型任意写本地文件或数据库。
