# 后续任务队列

此队列记录推荐顺序，不替代项目负责人在新会话中的最新指令。

## P0-A：恢复团队远端同步

目标：让本地 `main`、标签和 memory 能安全上传团队仓库。

验收：

- 当前 GitHub 身份拥有 `Decembered/ai-pet-conversation-agent` 写权限。
- `main` 配置远端跟踪分支。
- `git push` 和标签推送成功。
- 远端不包含 `conf.yaml`、数据库、日志、缓存和密钥。

## P0-B：自然语言喂食端到端验收

目标：验证最重要的产品纵向闭环，而不只是分别测试组件。

场景：用户说“给你吃一条鱼”。

验收：

- LLM 主动调用 `feed_pet`，而不是只用文字说吃过了。
- 同一 `request_id` 重试不会重复加状态。
- SQLite 中状态和事件一致更新。
- 页面状态自动刷新。
- Live2D 动作、显示文本和 TTS 与工具结果一致。
- 有自动化测试或可重复的 Demo 验收脚本。

## P0-C：冻结状态事件协议

目标：把前端 HTTP 刷新升级为明确的状态变更事件。

验收：

- 定义 `PetState` 和 `pet_state_changed` schema v1。
- HTTP/MCP 更新状态后，连接中的页面收到 WebSocket 事件。
- 前端以事件更新，重连时通过 HTTP 获取完整快照。
- 添加协议/路由测试和版本说明。

## P0-D：性能可观测性

目标：区分模型、视觉、TTS 和播放各自耗时，避免凭感觉优化。

验收：

- 记录 ASR 完成、LLM 首 token、首完整句、TTS 完成、首音频发送和前端播放完成时间。
- 日志不包含用户图片、完整私密文本或 API Key。
- 分别测量文本、语音、语音+图片三种路径。
- 根据数据决定是否压缩摄像头图片、降低发送频率或更换/配置 TTS。

## P0-E：发布 `0.1.x`

目标：在上述闭环和远端同步完成后形成可复现发布。

验收：

- 从空目录克隆后可按 RUNBOOK 启动。
- 完整测试通过。
- 更新变更日志、配置说明和 Demo 脚本。
- 确认 Live2D、头像、音色等资源许可。
- 新标签包含视觉、表情隐藏、TTS 平滑和项目 memory，而不是继续使用旧 `v0.1.0` 快照。

## P1：公共契约与下一阶段

在 P0 完成后，优先冻结：

- `PetGrowth`
- `MemoryRecord`
- `WorldEvent`
- `GeneratedArtifact`
- `PerceptionEvent`
- PersonaPack schema

随后选择一条纵向切片，建议优先级：

1. 跨会话长期记忆与可解释召回。
2. 四人格原子切换。
3. 写信并生成受控本地文件。
4. 绘画、作品索引和预览。
5. 摄像头存在/微笑等低风险事件与主动调度冷却。

不要同时开启所有 P1 模块；先冻结公共对象，再逐条做可观察的端到端闭环。
